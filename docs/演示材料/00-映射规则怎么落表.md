# 映射规则怎么落表（v2 — 必选 + 可选 + 三级排序）

> 这份是为了把"营销手填的 Excel 表"变成"系统里能自动跑"的最小化方案
> 核心发现：**项目原型已经能做了，你只差把 Excel 换成前端界面**
> v2 更新：**升级为「必选组 + 可选组 + hit_count + manual_priority」**（详见 ADR-015）

---

## 一、你说的问题

你贴的 Excel 表长这样：

| 产品 | 标签 |
|---|---|
| 渗漏 | 水路标签-卫生间漏水/水管老化/阳台漏水/厨房漏水 + 装修状态-5-10 年/未装修 |
| 刷新 | 环境标签-瓷砖开裂空鼓/墙面发霉/渗水返潮 + 家庭结构-三代同堂/多孩之家/二孩之家/三口之家 + 装修状态-5-10 年/未装修 |

**现在的做法**：你写死 SQL 筛。
**问题**：产品-标签关系变了，SQL 就要改。
**想要的**：业务在网页上点几下配置，后端自动按配置筛。
**升级诉求（v2）**：
- "5-10 年/未装修"是**硬性门槛**（没有就淘汰）
- "水路/环境/家庭结构"是**加分项**（命中 1 个就算）
- 命中更多标签的房主**优先**推送
- 标签打平时，营销**手动配置**优先级

---

## 二、新模型：必选组 + 可选组 + 三级排序

### 2.1 概念图

```
一条规则 = 硬性门槛（必选组）+ 加分项（可选组）+ 至少命中几个

       ┌──────────────┐         ┌──────────────┐
规则 R │ 硬性门槛     │   AND   │ 加分项       │
       │ 5-10年未装修 │ ──────► │ 命中 ≥1 个   │
       │ 必选全部命中 │         │ 任一即命中   │
       └──────────────┘         └──────────────┘
                                       │
                                       ▼
                              hit_count = 硬性命中 + 加分命中

多条规则都命中时，按三级排序挑胜出者：
   1. manual_priority ↑   营销手动配置（数字小者胜）
   2. hit_count     ↓     命中标签多者胜
   3. id            ↑     兜底（先入库者胜）
```

### 2.2 落表结构（`mapping_rule` 表字段）

```sql
mapping_rule (
  id                -- 主键
  name              -- 规则名（如"渗漏检测包"）
  packageId         -- 关联 product_package.id
  manual_priority   -- 营销手动维护的优先级（数字越小越靠前）
  mutexGroupId      -- 互斥组（同一组里只出一条）
  conditionJson     -- ★ 关键！结构为 {mandatory, optional, minOptionalHits}
  status            -- enabled / disabled
)
```

`conditionJson` 字段示例：

```json
{
  "mandatory": [
    { "tag": "decorate_status", "op": "in",
      "value": ["5-10 年", "未装修"] }
  ],
  "optional": [
    { "tag": "water_tag", "op": "contains_any",
      "value": ["卫生间漏水", "水管老化", "阳台漏水", "厨房漏水"] }
  ],
  "minOptionalHits": 1
}
```

**评估规则**：mandatory **全部命中** AND optional **至少命中 minOptionalHits 个** → 规则命中。

## 三、4 条示例规则（用新结构）

> 演示用 4 条规则，覆盖 3 个互斥组 + 1 个价格敏感组。

### 规则 1：渗漏检测包（硬性门槛 1 + 加分项命中 1 个）

```json
{
  "name": "渗漏检测包",
  "packageId": 1,
  "manual_priority": 1,
  "mutexGroupId": 1,
  "conditionJson": {
    "mandatory": [
      { "tag": "decorate_status", "op": "in",
        "value": ["5-10 年", "未装修"] }
    ],
    "optional": [
      { "tag": "water_tag", "op": "contains_any",
        "value": ["卫生间漏水", "水管老化", "阳台漏水", "厨房漏水"] }
    ],
    "minOptionalHits": 1
  },
  "status": "enabled"
}
```

**业务理解**：5-10 年/未装修 + 水路标签任意 1 个 = 命中。

### 规则 2：浴改淋升级包（硬性门槛 1 + 加分项命中 1 个）

```json
{
  "name": "浴改淋升级包",
  "packageId": 3,
  "manual_priority": 2,
  "mutexGroupId": 2,
  "conditionJson": {
    "mandatory": [
      { "tag": "decorate_status", "op": "in",
        "value": ["10 年以上", "未装修"] }
    ],
    "optional": [
      { "tag": "floor_plan", "op": "contains_any",
        "value": ["带浴缸"] }
    ],
    "minOptionalHits": 1
  },
  "status": "enabled"
}
```

**业务理解**：10 年以上/未装修 + 带浴缸 = 命中。

### 规则 3：墙面刷新包（硬性门槛 1 + 加分项命中 1 个）

```json
{
  "name": "墙面刷新包",
  "packageId": 2,
  "manual_priority": 3,
  "mutexGroupId": 1,
  "conditionJson": {
    "mandatory": [
      { "tag": "decorate_status", "op": "in",
        "value": ["5-10 年", "未装修"] }
    ],
    "optional": [
      { "tag": "env_tag", "op": "contains_any",
        "value": ["瓷砖开裂空鼓", "墙面发霉", "渗水返潮"] }
    ],
    "minOptionalHits": 1
  },
  "status": "enabled"
}
```

**业务理解**：5-10 年/未装修 + 环境标签任意 1 个 = 命中。

### 规则 4：价格敏感提醒包（无硬性门槛 + 加分项命中 2 个）

```json
{
  "name": "价格敏感提醒包",
  "packageId": 4,
  "manual_priority": 4,
  "mutexGroupId": 3,
  "conditionJson": {
    "mandatory": [],
    "optional": [
      { "tag": "price_sensitivity", "op": "in",
        "value": ["高", "中"] },
      { "tag": "activity_level", "op": "in",
        "value": ["近 30 天活跃", "近 7 天活跃"] }
    ],
    "minOptionalHits": 2
  },
  "status": "enabled"
}
```

**业务理解**：无硬性门槛，价格敏感 ∩ 活跃度 2 个都得中 = 命中。

## 四、命中示例（让业务一眼看懂）

| 房主标签情况 | 命中的规则 | 命中数 |
|---|---|---|
| 5-10 年 + 卫生间漏水 + 阳台漏水 | 渗漏(命中 3)、刷新(命中 2) | 渗漏胜出 (3 > 2) |
| 5-10 年 + 卫生间漏水 | 渗漏(命中 2)、刷新(命中 2) | 渗漏胜出 (manual_priority 1 < 3) |
| 10 年以上 + 带浴缸 + 卫生间漏水 | 浴改淋(命中 2)、渗漏(命中 1) | 浴改淋胜出 (2 > 1) |
| 高价格敏感 + 近 30 天活跃 | 价格敏感(命中 2) | 唯一命中 |

## 六、前端"条件编辑器"线框（升级版）

**业务在网页上看到的**（**禁出现 JSON / AND / OR / 互斥组等技术词**）：

```
┌────────────────────────────────────────────────────┐
│ 规则名: [墙面刷新包                       ]         │
│ 产品包: [墙面刷新包                       ▼]        │
│ 默认优先级: [3]  ← 数字小者靠前,打平时按这个排    │
│                                                     │
│ 硬性门槛 (硬性: 房主必须有这些标签,缺一不可)       │
│ ┌──────────────────────────────────────────────┐  │
│ │ [装修状态  ▼] [属于       ▼]                 │  │
│ │ 值: [5-10 年] [未装修] [+]                   │  │
│ │ [+ 添加硬性门槛]                              │  │
│ └──────────────────────────────────────────────┘  │
│                                                     │
│ 加分项 (加分: 命中越多越优先,至少命中几个)         │
│ ┌──────────────────────────────────────────────┐  │
│ │ [环境标签  ▼] [包含任一    ▼]                │  │
│ │ 值: [瓷砖开裂] [墙面发霉] [+]                │  │
│ ├──────────────────────────────────────────────┤  │
│ │ [家庭结构  ▼] [属于       ▼]                 │  │
│ │ 值: [三代同堂] [多孩之家] [+]                │  │
│ ├──────────────────────────────────────────────┤  │
│ │ [+ 添加加分项]                                │  │
│ └──────────────────────────────────────────────┘  │
│                                                     │
│ 至少命中几个: [1] 个加分项                          │
│  ↑ (1=任一即命中,2=至少两个,最大不超过加分项数)    │
│                                                     │
│ ── 命中预览 (业务能配之前先看到会圈中多少) ──     │
│ 预计命中: 约 8,200 户 (占 5-10 年未装修池 6.5%)   │
│                                                     │
│ [取消]                              [保存]         │
└────────────────────────────────────────────────────┘
```

**列表页排序展示**（让业务一眼看出"匹配度"）：

```
┌──────────────────────────────────────────────────────┐
│ 规则                  默认优先级  匹配度  预计命中    │
├──────────────────────────────────────────────────────┤
│ 渗漏检测包            1           -       -          │
│ 浴改淋升级包          2           -       -          │
│ 墙面刷新包            3           -       -          │
│ 价格敏感提醒包        4           -       -          │
└──────────────────────────────────────────────────────┘

↑ 房主"匹配度"是评估时的实时数据,不出现在列表里;
  列表只显示规则本身的优先级
```

## 八、给开发领导讲的一句话

> "这套映射规则采用**必选组 + 可选组**的两层条件结构。多规则按**人工优先级 → 命中数 → 入库顺序**三级排序。条件表达式以 JSON 存进 mapping_rule.conditionJson，业务在前端零代码维护。规则结构升级详细见 ADR-015。"
