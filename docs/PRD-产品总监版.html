Context

01现状问题与目标用户

链路被拆成四段独立的人工操作，每段都有结构性断点。
#环节当前做法结构性断点
1 人群圈选 人工用 Excel 按标签筛选目标房屋 重复劳动；筛选口径不统一、跨人不可比；易错
2 产品匹配 依赖个人经验判断「哪类房屋推哪个产品包」 经验不可沉淀、不可复用、不可审计；人员变动即断档
3 海报制作 逐张手工设计制作 无法个性化、无法规模化；产量直接受人力上限约束
4 触达下发 名单整理后交平台批量群发 无频次控制 → 重复触达引发投诉与拉黑；无发送记录 → 不可追溯、不可补推

目标用户

主营销管理岗 · 总部
  • 职责：维护产品包、配置「产品包 × 标签」映射规则、设定频控策略
  • 核心诉求：规则配一次能长期复用；不会配错、不会推错人；推完有数据可汇报
  • 能力边界：熟练使用 Excel 与后台管理界面，不具备 SQL 与规则引擎能力
次大区 / 营业部运营
  • 职责：发起推送、查看执行结果、对重点客户手动重推
  • 核心诉求：判断当天推荐是否合理；未发送的能查到原因；能对指定对象补推
  • 能力边界：熟悉企微与短信后台，能读懂数据表格

Core Mechanisms

03三个核心机制

本期系统的产品价值集中在这三个机制上，均已由原型验证。
A映射规则模型
  • 实体：产品包为单一实体，清单由业务方自行维护；不含 SKU、价格、库存、订单
  • 规则结构：条件（标签表达式）→ 动作（推荐产品包）
  • 冲突消解：优先级排序 + 互斥组；同一房屋、同一周期收敛为单一产品包
  • 配置体验：保存前提供命中预览（预计命中户数、组内冲突与胜出规则提示）
B频控模型（P0 一等功能）
  • 名单类：退订名单、黑名单，按号码与房屋双键校验
  • 冷却类：房屋冷却 7 天｜产品包冷却 30 天｜线索静默（同包 90 天 / 客户 15 天）
  • 频次类：房屋日 1 / 周 2 / 月 4 次｜全局日上限 5000 条
  • 时段类：可发窗口 10:00–12:00、15:00–18:00｜22:00–08:00 硬禁发
  • 数据缺失时 fail-open（放行并告警），避免因上游断数误停业务
  • 全部拦截落盘并给出原因码，可解释、可重推
C归因模型
  • 窗口：15 天，固定常量不可配置
  • 口径：首触 / 末触双模型回填，明细可追溯至 lead_count
  • 数据来源标注：外部未标注产品包时记为 inferred，不与外部数据混算准确率
  • 口径声明：「触达」= 发送成功，非已查看；相关 ≠ 因果，看板强制标注
合规前置：频控阈值（冷却天数、日上限、禁发时段）需经业务与合规书面认可后方可正式发送；退订名单必须形成回流闭环，否则不得开启真实触达。

AI Positioning

04AI 的角色与边界

本节回答一个必须先对齐的问题：这个系统的"智能"来自哪里。
结论：系统的自动化能力来自规则引擎 + 数据驱动，而非模型推理。生成式 AI 在本链路中定位为可选增强， 不承担圈选、匹配、频控、发送等任何主链决策——这保证了结果可解释、可审计、可复现，也符合营销场景对"可控"的硬要求。
链路环节执行主体产品说明
人群圈选规则引擎规则由业务自行配置，支持保存前命中预览，随时可调整
产品匹配规则引擎优先级 + 互斥组收敛，同一房屋同期只输出一个产品包
频控校验规则引擎14 项闸门硬约束，不通过即落盘原因码
海报生成模板套版
变量填充 + 图像合成		 按房屋真实标签自动选择痛点文案并套用模板；单张 20–200ms，边际成本趋近于零，文字零错字
背景素材生产生成式 AI
离线 · 可选		 可用生成式 API 批量产出背景图素材池，经人工审核后入库作为模板背景，不在跑批链路内调用

决策依据：为什么主链路不采用生成式出图

维度生成式出图模板套版（采用）
成本约 0.2 元/张；日发 5000 张 ≈ 3 万元/月，成本随发送量线性增长边际成本趋近于零，复用自有算力
准确性中文渲染不可控，存在错字风险；横幅含小区名、联系方式等零容错字段文本层由变量注入，零错字
时延单张数秒（异步任务），无法满足 T+1 单批次产出单张 20–200ms，单批可分钟级完成
可回归性同输入不同输出，问题不可复现，抽查与验收困难同输入同输出，可抽查、可验收
个性化的实现路径
  • 「个性化」的诉求被保留，但实现方式从「模型逐张现画」调整为「模板 + 变量逐张组装」
  • 推送内容由房屋自身标签决定
  • 海报痛点文案取自该房屋真实标签（如"墙面发霉"）
  • 社会证明仅在真实数据达标时展示，禁止编造数字
生成式出图的启用条件（满足其一）
  • 单批实验量 ≤ 200 张，且已设定成本上限与人工复核
  • 用于背景素材池生产，人工审核后入库
  • 业务明确接受成本与不可复现性，并书面确认
不满足上述条件时默认不开启，跑批链路中不出现任何生成式调用。
二期演进方向：基于归因结果自动优化规则权重、辅助生成人群定向文案。仍以「人在环上确认」为前提，不引入自动决策。

Scope & Metrics

05范围边界与成功指标

一期范围（In Scope）

本期交付
  • 三源数据接入 + 映射规则配置（优先级排序、命中预览）
  • 每日跑批 + 14 项频控闸门 + 发送时间窗口
  • 模板套版个性化海报（零错字，边际成本趋近于零）
  • 推送明细、原因码分布、单条重推、批次停止
  • 短信 / 企微通道对接（由外部通道团队拉通）
  • T+1 归因看板
一期明确不做（Non-goals）
  • 生成式 AI 出图进主链路（降级为可选背景素材池）
  • 点击 / 短链归因（依赖通道能力，待通道团队确认）
  • 撤回已送达短信（物理不可行，产品不承诺）
  • AI 自动调规则、无互动自动降频、多包同推
  • 自建 CDP / MA 平台级能力（出价、跨渠道归因建模）
  • 改动上游生产数据仓库（生产 SQL 零改动，仅新增同步节点）

成功指标

层级指标定义与口径说明
北极星单位触达的线索产出归因窗口内产生的去重线索数 ÷ 成功触达数，仅统计同口径数据源
过程指标号码覆盖率可解析出有效号码的房屋占比，≥70% 为发送前置门槛
规则命中率命中任一规则的产品包候选房屋占比，用于评估规则覆盖度
拦截率与原因码分布按 14 类原因码分布，用于定位是数据缺口还是频控生效
发送成功率 / 重推率通道回执成功占比；人工重推占比反映规则与数据质量
验收门槛（DRY_RUN 摘除条件）：号码覆盖率 ≥ 70% 且频控合规口径获书面认可，两项同时满足方可开启真实发送； 覆盖率未达标时系统仅生成待发送清单、不执行发送。

Dependencies & Risks

06外部依赖、风险与待决策项

外部依赖

依赖项归属方状态与影响
T+1 标签数据同步数据团队同步方式待架构确认；未就绪时跑批自动中止并告警
短信 / 企微通道对接外部通道团队通道存在已确认，接口标准待拉通；影响发送层与点击归因可行性
海报素材与品牌规范业务 / 设计未提供时模板规格无法冻结，海报页仅能占位
产品清单与产品包定义业务方业务自行维护，系统不介入

主要风险

  • R1 通道能力未确认：是否支持回执、带参短链直接决定点击归因能否纳入一期
  • R2 上游数据缺口：「浴改淋」产品包依赖的户型标签数据源未接入，系统已锁定该包不可启用
  • R3 合规闭环未定：营销授权来源与退订回流方式未确认，缺失则不能正式发送
  • R4 素材未定：海报模板规格无法冻结，影响 M2 交付
  • R5 需求实现方式变更：海报由"AI 生成"调整为"模板套版"，需书面确认以防验收争议
  • R6 覆盖率不达标：号码覆盖率若长期低于 70%，系统将持续处于"只出清单不发送"状态
