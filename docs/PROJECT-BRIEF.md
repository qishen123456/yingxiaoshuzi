## 1. 一句话定义

把「标签圈人 → 判断推什么产品 → 做海报 → 发短信」这条**目前全人工线下**的链路，用一个内部系统串起来：
营销管理配一次「产品包 × 标签」映射规则，系统每日按 T+1 数据自动圈人、匹配产品包、生成个性化海报、产出待发送清单并记录下发结果。

## 2. 用户已拍板的约束（不可推翻）

| # | 决策项 | 用户原话/结论 | 对系统的影响 |
|---|--------|--------------|-------------|
| 1 | 产品包 | 「应该一个产品包」，产品清单由业务方自己维护 | 系统只做单一产品包实体；**不做** SKU/价格/库存/商品中心 |
| 2 | 映射规则 | 「映射应该需要优先级加互斥」 | 规则模型必须支持 **优先级排序** + **互斥组**；需命中预览 |
| 3 | 触达通道 | 「有现成的通道，可以让开发去拉通」 | 本系统**不自建通道**，只提供数据出口 + 任务与记录 |
| 4 | 推送记录与重推 | 「推送也要有记录也要手动重推着走」 | 推送明细可查；支持**单条/批次手动重推** |
| 5 | 数据节奏 | 「数据是 T+1 的，一天推一次就行了」 | 每日一次跑批；数据源 MaxCompute T+1 快照 |
| 6 | **频控（P0）** | 「要控制推送时间，还有推送的规律，不能天天推，会被骂死了」 | **推送时间窗口 + 推送频次规律 是一等功能，非可选优化** |
| 7 | 规模定位 | 「总之这是一个小的系统功能了」 | 严格克制范围，**不上**微服务/消息队列集群/大数据平台 |

### 频控必须覆盖的具体能力（由 #6 推导，请 PM 落进 PRD、架构师落进表设计）
- 可发送时间窗口（如仅 10:00–19:00，可配置，含节假日策略）
- 同一房屋冷却期（N 天内不重复推）
- 同一产品包冷却期
- 同一房屋每日/每周最大推送次数
- 单次任务/每日全局发送量上限
- 同一家庭（同地址/同业主）去重
- 退订名单与黑名单（且退订必须可回流）

|--------|------|-----------------|

## 4. 目标链路（7 环节）

```
标签数据基座 → 人群圈选 → 映射配置(新增·核心) → 推荐匹配 → AI 海报生成 → 多渠道触达下发 → 效果回流(二期)
```

**一期范围**：圈选 → 映射 → 推荐 → 生成 → 触达（实线部分）
**二期范围**：效果回流（虚线部分）——一期拿不到点击/转化回流时，硬做只会变成假数据看板

---

## 5. 非目标（Out-of-Scope）

- 不自建短信/企微通道（走公司现有通道，由外部开发团队拉通）
- 不做电商级商品中心（无 SKU、价格、库存、订单）
- 不做 C 端触点（不做小程序/App 给业主用）
- 不做 CDP / MA 平台级能力（不做出价、不做跨渠道归因建模）
- 一期不做效果回流分析看板

## 7. 团队级 P0 绝对规则（每个 Phase 门禁必查）

1. **禁止 emoji 作为功能图标**，图标必须来自 Spec 锁定的**同一套** SVG 图标库，尺寸 16/20/24px。
2. **禁止紫色→粉色渐变主视觉**（Indigo→Pink + 发光边框 + 毛玻璃三位一体）。
3. **禁止硬编码颜色**（唯一例外 #fff / #000），颜色必须走 Design Token。
4. **禁止 AI 模板味代码与文案**（Lorem ipsum / Welcome to Our App 之类）。
