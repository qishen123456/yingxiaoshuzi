## 零、先花 3 分钟搞明白这是啥

**把整个系统想成一个"自动营销车间"。**

```
  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
  │   仓库      │ ──→ │   机器      │ ──→ │  操作台     │
  │  数据库     │     │  后端程序    │     │  前端网页    │
  │             │     │             │     │             │
  │ 存 125.7 万 │     │ 每天自己醒来 │     │ 你坐着配规则 │
  │ 户房子档案   │     │ 挑人、发短信 │     │ 看结果      │
  └─────────────┘     └─────────────┘     └─────────────┘
                             ↑
                        ┌─────────────┐
                        │   闹钟      │
                        │  定时任务    │
                        │ 每天 7:30   │
                        │ 叫机器开工   │
                        └─────────────┘
```

- **仓库** = 数据库。存着所有房子的档案（哪户漏水、装修几年、电话多少）。
- **机器** = 后端程序。真正干活的，每天自己跑一遍：挑出今天该推的房子 → 检查会不会打扰 → 生成海报 → 发出去。
- **操作台** = 前端网页。你打开浏览器看到的那个界面，用来配规则、看结果。
- **闹钟** = 定时任务。每天到点自动叫机器开工，不用人管。

**好消息：这个车间的地基和主要机器，已经有人搭好了。**

搭好的是：仓库的图纸（21 张表格）、最核心的机器（挑人、检查打扰、算效果）。

**你要做的：把没装完的几台机器装上。**

没装完的一共 8 件，后面会一件件说。

> **提醒**：这个项目用的是 **Node.js** 语言写的，跟你平时用的 Python 不是一套。没关系，你不需要写代码也能把它跑起来 —— 大部分时间你是在敲我给你的命令。

## 第一步：检查工具（5 分钟）

你需要三样东西。先打开"终端"看看有没有。

### 怎么打开终端

按 `Command + 空格`，输入 `终端` 或 `Terminal`，回车。

> **终端是什么**：就是那个黑底白字的窗口，你在里面敲命令，电脑就照做。别怕，敲错了不会坏。

### 检查三样工具

把下面这行**整行复制**，粘贴到终端里，按回车：

```bash
echo "--- 检查 Docker ---"; which docker || echo "❌ 没装 Docker"
echo "--- 检查 Node ---"; node -v || echo "❌ 没装 Node"
echo "--- 检查 Git ---"; which git || echo "❌ 没装 Git"
```

**你会看到三种情况：**

| 看到什么 | 什么意思 | 怎么办 |
|---|---|---|
| 三行都有内容（比如 `v22.22.2`） | 全都有，太好了 | 跳到第二步 |
| 某一行出现 ❌ | 那个没装 | 看下面 |

**如果缺 Docker**：去 `docker.com` 下载 "Docker Desktop for Mac"，装好后打开它（右上角会出现一只小鲸鱼图标，等它变绿）。

**如果缺 Node**：去 `nodejs.org` 下载 LTS 版本（要 **22 以上**），一路点下一步装完。

**如果缺 Git**：Mac 一般自带。真的没有就装个 Xcode 命令行工具，终端里敲 `xcode-select --install`。

**目标**：让这个车间先跑起来，你能在浏览器里看到界面。

> `cd` 是 "change directory" 的缩写，意思是"走进这个文件夹"。回车后没任何提示是正常的，说明成功了。

### 2.2 启动"仓库"（数据库）


**说明**：`-d` 是"在后台悄悄运行"的意思。Docker 会在你电脑里启动一个 PostgreSQL 数据库。

看到 **STATUS** 那列写着 `Up` 或 `healthy` 就成了。如果是 `starting`，等 10 秒再敲一次。

### 2.3 装"机器"需要的零件

```bash
cd backend

```

> `backend` 是后端的文件夹。`npm install` 是"把程序需要的零件下载下来"。

**说明**：这一步要下载几百个小文件，**慢，可能要 2-5 分钟**。屏幕上会滚一堆文字，正常，别关。

**看到什么算对**：最后出现类似 `added 500 packages in 30s` 的字样，回到命令行等待状态。


> `prisma` 是个工具，负责"在数据库里把表格建出来"。第一条是"准备工具"，第二条是"真的建表"。

**看到什么算对**：第二条跑完后提示表格建好了。如果中途问你什么（比如输入名字），直接按回车用默认值。

### 2.5 塞点示例数据进去

> `seed` 是"种子"的意思。这一步会往空表里塞进一些基础数据（比如有哪些标签、有哪些产品包）和一批演示用的房子，好让系统能跑起来看效果。

## 第三步：看懂车间布局（15 分钟，不用写代码）

### 3.1 文件夹都是干嘛的

用"访达"打开项目文件夹，你会看到这几个：

| 文件夹 | 大白话解释 |
|---|---|
| `backend/` | **机器本体**。所有干活的逻辑都在这。你 80% 的时间会碰这里 |
| `frontend/` | **操作台界面**。你在浏览器看到的那些页面 |
| `sql/` | **给数据仓库用的脚本**。数仓同事要用这些把数据搬过来 |
| `docs/` | **说明书**。设计文档、接口约定都在这 |
| `demo/` | 一个演示用的网页 |
| `资料/` | 业务资料（SQL、客群清单等） |
| `docker-compose.yml` | 启动仓库的配置文件 |

### 3.2 三张最重要的表格

记住这三张，后面全靠它们：

**① `house_label_snapshot` —— 房屋档案表**
每一行是一套房子。里面记着：这套房子漏水不漏水、装修几年了、家里几口人、电话多少。
一共有 **125.7 万行**。

**② `mapping_rule` —— 规则表**
每一行是一条规则，比如"漏水 + 装修 5 年以上 → 推荐防水补漏包"。
**这张表是业务同事自己配的**，配一次，天天用。

**③ `push_detail` —— 推送记录表**
每一行是"给某套房子发过一条"，记着：什么时候发的、成功没、如果没发是什么原因。

### 3.3 怎么"偷看"表格里的数据

在终端里敲这行：

```bash
cd /Users/ltq/Desktop/working/专项/研选营销智能推送系统 && docker compose exec db psql -U marketing -d yanxuan_marketing
```

你会进入一个 `yanxuan_marketing=#` 的提示符。然后可以敲 SQL 看数据：

```sql
select count(*) from house_label_snapshot;
```

（看有多少套房子）

```sql

```

（看有哪些规则）

**看完想退出**：输入 `\q` 回车。

## 第四步：五个阶段，一个一个来

> **重要**：顺序不能乱。第一阶段的活没干完，后面几个阶段的验收根本验不了。

### 阶段一：把真实数据接进来

**这一步在干嘛（大白话）**

现在仓库里的房子数据是"演示数据"（假的）。要让系统真能用，得把公司真实的 125.7 万户数据每天自动搬进来。

**具体要做的事**

1. **找数仓同事**，让他把 `sql/` 文件夹里那三个 SQL 配成"每天自动跑"的任务。
   - 三个 SQL 分别负责搬：房子档案、电话号码、线索记录
   - 分别设成每天 02:00、02:10、02:30 跑
   - **要求**：只读公司原来的数据，不许改动上游

2. **等第二天**，看数据有没有进来。终端里敲：

```bash
cd /Users/ltq/Desktop/working/专项/研选营销智能推送系统
docker compose exec db psql -U marketing -d yanxuan_marketing -c "select count(*) from house_label_snapshot;"
```

3. **看"电话号码覆盖率"** —— 这是第一个硬指标：

```bash
docker compose exec db psql -U marketing -d yanxuan_marketing -c "
  select
    count(*) as 总房子数,
    count(*) filter (where contact_mobile_enc is not null) as 有电话的,
    round(100.0 * count(*) filter (where contact_mobile_enc is not null) / count(*), 2) as 覆盖率百分比
  from house_label_snapshot;"
```

**✅ 做对了的标准**：`覆盖率百分比` **≥ 70**。

**❌ 没到 70 怎么办**：这是数据问题，不是代码问题。要去找数仓和业务，问为什么这么多房子没电话。**没到 70 之前，系统不会真的发短信**（这是故意的保护）。

**这活要什么人来干**：数仓同学（配同步任务）+ 你（验证数据）

### 阶段二：把规则配置做完整

**这一步在干嘛（大白话）**

让业务同事能在界面上自己配规则，配的时候能看到"我这条规则大概会圈中多少户房子"，配错了能及时发现。

**具体要做的事**

1. 打开 `backend/src/modules/rules/` 文件夹，这是规则相关代码
2. 有一个"规则预览"的功能要补 —— 就是让业务点一下按钮，系统算出"这条规则会命中多少户"
3. **注意**：125 万行数据不能傻算，得让它在后台慢慢算，算好了再给结果（不然页面会卡死）
4. 还有"拖动排序"—— 规则的优先级能拖着调整

**✅ 做对了的标准**：
- 在界面上新建一条规则，点"预览"，能看到"预计命中 X 户"
- 把这条规则拖动到另一条上面，优先级真的变了

**这活要什么人来干**：后端开发（1-2 天）

### 阶段三：接通短信通道 ⚠️ 会卡住

**这一步在干嘛（大白话）**

现在的"发送"是**假的**——程序假装发出去了，其实没发。要接上公司真实的短信/企业微信通道，才能真发。

**这一步不取决于你**

发送通道是**别的团队**在管。你需要先找他们要一份"接口文档"，说明：
- 怎么调用他们的发送功能
- 发出去以后怎么知道成功了
- 有没有发送频率限制

**⚠️ 这件事今天就该发邮件/找人说。** 它不取决于你写代码快不快，取决于别人什么时候给你文档。

**拿到文档后要做的**

1. 写一段代码，把"发送"这个动作真的发到他们系统去
2. 接收他们返回的"发送结果"，记到 `push_detail` 表里
3. 加一个"停止发送"按钮 —— 发现不对能立刻停
4. 加**报警**：半夜跑批失败了，要能通知到人（不然没人知道）

**✅ 做对了的标准**：
- 先把每天发送上限调到 20 条测试
- 触发一次，去 `push_detail` 表里看，状态是"已发送"，而且有真实的通道单号（不是 `mock-` 开头的假的）

**这活要什么人来干**：后端开发（3-5 天）+ **外部通道团队给文档**

## 第五步：什么时候能真的发短信？

有**两个门槛，必须同时满足**：

| 门槛 | 谁说了算 |
|---|---|
| 1. 电话号码覆盖率 ≥ 70% | 数据说了算（要等数仓把数据搬完才知道） |
| 2. 频控规则（几天发一次、什么时间不能发）经业务和合规**书面认可** | 业务 + 合规说了算 |

两个都满足了，才能把配置里的 `DRY_RUN=true` 改成 `false`，开始真发。

**在这之前**，系统每次跑批只会生成"待发送清单"，不会真发。

> 为什么要这么严？因为发短信是**不可撤回**的。发错了就是打扰客户，会被投诉。

## 卡住了怎么办

### 常见问题对照表

| 你看到的现象 | 什么意思 | 怎么办 |
|---|---|---|
| `command not found: docker` | 没装 Docker | 回去装 Docker Desktop，装完**要打开它** |
| `command not found: npm` | 没装 Node | 去 nodejs.org 装 LTS 版 |
| `Port 3000 is already in use` | 3000 端口被别的程序占了 | 终端敲 `lsof -ti:3000 \| xargs kill -9` 杀掉它 |
| `Port 5434 is already in use` | 数据库端口被占了 | 换个端口，或者关掉占用的程序 |
| `npm install` 卡住不动 | 网络慢 | 等着，或者断了重敲一次 |
| `Can't reach database server` | 数据库没起来 | 敲 `docker compose ps` 看状态，没起来就 `docker compose up -d db` |
| 界面打开是白的 | 前端或后端没起来 | 检查两个终端窗口是不是都还开着 |
| 一堆红色 ERROR | 某一步没做 | 从"第二步"重新按顺序走一遍 |

### 三条通用原则

1. **红色报错不要慌**：把报错最后几行复制下来，搜一下，或者发给我看
2. **按顺序来**：跳步骤是绝大多数问题的来源
3. **两个终端窗口别关**：一个跑后端、一个跑前端，关了就断了

| 顺序 | 干什么 | 大概要多久 | 会不会被别人卡住 |
|---|---|---|---|
| 1 | 第二步跑通（今天就做） | 30 分钟 | 不会 |
