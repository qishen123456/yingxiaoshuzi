# ADR-014: 项目定位为「效率工具」、一期效果降标准、规则责任归营销管理岗

## Status

Accepted (2026-10-08)

## Background

Phase 0 需求澄清阶段，项目总监提出三个岔路口请用户拍板，用户于 2026-10-08 给出结论：

1. **项目定位**：是「效率工具」（把人工链路自动化、省人力），还是「经验沉淀平台」（把人脑判断变成可复用资产）？
2. **一期是否做效果回流**：不做 / 降低标准做 / 把二期提前？
3. **谁对「规则配得对不对」负最终责任**：业务负责人 / 营销管理岗 / 其他？

这三条都会改变后续的优先级排序与设计取向，故落为 ADR。

## Decision

### D1 — 项目定位：效率工具

**定位为「把人工链路自动化，省人力」的效率工具**，而非「经验沉淀平台」。

对系统的直接影响：
- 成功标准是**「省了多少人力」**，且必须可量化（见 Consequences 补充）
- 优先级向「跑得快、少出错、少人工介入」倾斜
- 不额外设计「知识资产化」相关能力（如经验图谱、规则版本演进分析等）
- 但**规则的可配置性仍需保留** —— 因为 D3 明确了规则由营销管理岗自己维护

### D2 — 一期保留效果回流，但降低标准

**不做全链路双模型归因**（首触/末触），改为**简化版效果参考**：

| 保留 | 不做 |
|---|---|
| 「某条推送 → 15 天内该房屋是否产生线索」的简单关联 | 首触/末触双模型回填 |
| 效果数据在看板上展示 | 归因准确率宣称 |
| `lead_record` 数据接入（数据同步阶段本来就要做） | 个体级因果判定 |

**强制约束**：看板必须显著标注「**参考值，非归因结论，不可用于个体判定**」。降标准 ≠ 可以含糊，口径必须写在界面上。

### D3 — 规则正确性的最终责任人：营销管理岗

**由总部营销管理岗（PRD 中的主用户）对「规则配得对不对」负最终责任**。

对系统的直接影响：
- 规则配置体验从「重要」**升级为生死线** —— 她不是技术人员，必须做到**零培训可用**
- 必须配套三件套：**命中预览**（配之前先看会圈中多少）、**冲突提示**（组内重叠时告知谁胜出）、**可回滚**（配错能撤回）
- **她的能力边界 = 系统复杂度的上限**。超出她理解范围的设计，等于整条链路卡在她这里

## Consequences

### 正面

- 定位明确，避免「既要省人力、又要做知识资产」造成的范围膨胀
- 效果降标准换来了**一期可控**，避免在没有数据源时硬造假看板
- 责任人明确，规则配错有人认账，不会出现「技术说业务没讲清、业务说技术配错」的扯皮

### 负面 / 必须处理

**① 「省人力」的证明问题（这是本决策最重要的待解项）**

D1 定位为效率工具 → 价值必须可证明；但 D2 又把效果降为标准参考 → **效果数据不再能用来证明「省了人力」**。

两者叠加会产生一个尖锐的内部质疑：**「你说省人力，凭什么？」**

**解法：用过程指标证明，不用效果指标证明。**

过程指标是确定的、一期就能算出来的、不依赖归因的：

| 环节 | 人工基线（需实测） | 系统自动化后 | 省下的人力 |
|---|---|---|---|
| 圈选：筛 125.7 万户 | 人工拉表 __ 人天/次 × 频次 | 每日自动 | 差值 |
| 海报制作 | 手工 __ 分钟/张 × 张数 | 20–200ms/张，自动 | 差值 |
| 名单整理与分发 | 人工 __ 人天/次 | 系统自动下发 | 差值 |
| 推送记录与追溯 | 人工查证、无法量化 | 全量留痕，秒级可查 | 差值 |

**行动项：这三张表的人工基线值必须在开工前问业务要真实数据**，否则「效率工具」的价值无法被证明，项目在有预算压力时最先被砍。

**② 效率工具的价值容易被质疑为「可替代」**

必须回答：如果只是省人力，裁两个人不就行了？

答法不是辩解，而是把省下的人力**显性引向更高价值的工作**：从「手工拉表做图」转向「优化规则、跟进线索」。这一点需要在向管理层汇报时主动说清。

**③ 规则配置页的复杂度与规则表达力存在冲突**

D3 把可用性提到生死线，但业务又需要「优先级 + 互斥组 + 多条件组合」的表达力。两者天然紧张。
处理原则：**表达力做减法，把复杂度收进系统内部**。宁可规则类型少而稳定，也不要给营销管理岗一个「什么都能配」但配不明白的配置器。

**④ 降标准的效果数据有被误读风险**

业务看到「转化率」一定会当 KPI 用。必须在 UI 层强制标注，并在交付培训时明确说明口径边界。
