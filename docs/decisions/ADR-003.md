# ADR-003: 前端使用 React 19 + Ant Design 5 + Vite 7

## Status

Accepted (2026-09-18)

## Background

本系统前端是**内部营销管理后台**：重表格、重表单、重配置（规则可视化、命中预览、频控配置、明细查询与重推）。团队 P0 规则要求颜色必须走 Design Token、禁止硬编码颜色。

候选：

| 候选 | 版本 | 后台适配 | 表格/表单 | Design Token | SSR 收益 |
|------|------|----------|-----------|--------------|----------|
| React + Ant Design | React 19.x / antd 5.x / Vite 7.x | 强 | 强 | 强（ConfigProvider theme） | 无 |
| Vue 3 + Element Plus | Vue 3.5 / Element Plus 2.x | 强 | 强 | 中 | 无 |
| Next.js 15 + antd | Next 15.x | 中 | 强 | 强 | 对本项目无收益 |

## Decision

选择 **React 19.x + Ant Design 5.x + Vite 7.x + TypeScript**。

理由：
1. 管理后台的核心是复杂 Table（虚拟滚动、可展开、筛选）与 Form（校验、联动），antd 的成熟度最高。
2. antd 5 的 CSS-in-JS Design Token 体系通过 `ConfigProvider theme={{ token }}` 注入，与 P0「颜色走 Token」天然契合，token 集中定义、组件引用。
3. 纯 SPA 即可，Next.js 的 SSR 对本项目无业务收益，反而增加部署复杂度，否决。
4. Vue 3 + Element Plus 作为备选（若团队 Vue 栈更强）。

**已知坑（必须写进实现）**：React 19 与 antd 5 需安装官方兼容包 `@ant-design/v5-patch-for-react-19` 并在应用入口 `import` 一次，否则 `Modal` / `Notification` / `Message` 的静态方法与波纹特效失效（hooks 调用方式不受影响）。

## Consequences

正面：
- 后台开发效率高，表单/表格开箱即用。
- Design Token 与 P0 颜色规则一致。

负面：
- antd CSS-in-JS 有少量运行时开销（对内部后台可忽略）。
- 需维护 React 19 兼容补丁的引入。
