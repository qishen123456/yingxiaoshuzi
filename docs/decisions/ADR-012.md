# ADR-012: 点击埋点按通道能力二选一（条件性 P0），落地页埋点一期不做

## Status

Accepted (2026-09-18)；**Superseded-in-part（2026-09-18 修订）**：原「点击埋点固定 P1」改为**条件性 P0**，见下方 Decision 与「修订记录」。

## Background

业务方要求「推完看效果」。需要判断：漏斗要测哪些环节？是否需要在前端（落地页/海报）埋点？

归因链路可拆为三段：**发送 → 点击 → 留资（线索）**。三段分别需要不同数据来源：

| 环节 | 需要什么 | 数据来源归属 |
|------|----------|--------------|
| 发送侧 | 发送时间、对象、产品包、海报、状态 | 本系统自有 |
| 点击侧 | 带参短链 + 点击回执（谁点了哪一条） | 外部通道（短信/企微） |
| 落地页侧 | 落地页曝光 / 表单留资回传 | 落地页归属方（非本系统） |

候选：

| 候选 | 覆盖漏斗 | 成本 | 前置依赖 |
|------|----------|------|----------|
| A 仅发送侧记录 | 两端（发送量、线索量） | 零（自有表） | 无 |
| B 发送 + 点击埋点 | 三段 | 中（需 `click_event` 表 + 接收接口 + 通道短链） | 外部通道提供带参短链与点击回传 |
| C 发送 + 点击 + 落地页埋点 | 全漏斗 | 高（还需落地页归属方协作埋点/回传） | 通道 + 落地页方双重依赖 |

## Decision

**发送侧（A）必做**：只保留发送侧记录（`push_detail` 自有），不新增落地页埋点（C 的落地页部分一期明确不做，缺数据源且依赖落地页归属方）。

**点击侧按通道能力二选一（条件性 P0，不由本系统预设）**：
- 若外部通道**能**提供**带参短链 + 点击回传** -> 点击埋点**升 P0**，一期就做「发送 → 点击 → 留资」三段漏斗（设计与 DDL 见 ARCHITECTURE.md §15.6 附录，条件启用）。
- 若**不能** -> 点击埋点保持 P1，看板如实标注数据缺口（只算两端）。

判定依据：实现成本可控（本系统仅需 `click_event` 表 + 接收接口 + `push_detail.link_token`），瓶颈完全在通道侧能力，故**交由通道能力决定**，而非我方预设——通道一旦确认即可直接进 Spec，不必重走设计。

理由（为何不无条件做点击埋点）：
1. 点击侧非本系统可控，强行无条件 P0 会引入一处外部阻塞，与「不被外部依赖卡死」的硬边界冲突。
2. 但一旦通道能提供，点击数据即可把漏斗中段（文案/海报吸引力 vs 落地页转化力）分辨出来，价值明确，故宜升 P0 而非长期 P1。

**契约纪律**：即使升 P0，§15.6 的 `click_event` 表与接口在**通道确认前不进 `openapi.yaml`**——理由同「无互动降频」：契约里存在但不生效的端点/枚举最易被误实现为半成品。

理由：
1. 一期目标是「把线下四段流程串起来 + 能看出每次发送后的线索质量」，发送量↔线索量两端即可回答；发送侧数据本系统自有，**无需任何埋点即可获得**，零成本零依赖。
2. 点击侧与落地页侧**均非本系统可控**（依赖外部通道与落地页归属方），无条件强行落地会引入外部阻塞，与「不被外部依赖卡死」的硬边界冲突——故不自设，而**按通道能力二选一**。
3. 落地页侧一期明确不做（连候选 A 的两端都够用，落地页回传依赖归属方协作，投入产出比最低）。

**必须写入契约与看板的诚实声明（不可省略）**：
- 一期（未启用点击埋点时）「触达」= **发送成功**（`status=sent`），不是「已查看」；归因是**发送相关性**，非因果关系。
- 看板所有转化指标必须标注该局限（见 ARCHITECTURE.md §15.3 / §15.4、api-spec 看板 schema 描述）。
- 启用点击埋点后，局限收窄为「留资归因 = 点击相关性」（仍非因果）。

## Consequences

正面：
- 默认（通道不支持点击回传）：零新增埋点表/接口，一期不被卡，归因口径简单可审计。
- 通道支持时（升 P0）：漏斗细化为「发送 → 点击 → 留资」三段，可分辨中段流失（文案/海报 vs 落地页）。

负面（**关键盲区，必须显式承认**）：
- **未启用点击埋点时**：「**发了但没线索**」与「**看了但没留资**」在一期数据上**无法区分**（都表现为「已发送 + 无线索」）。
- 未启用时漏斗只能算两端，**无法算点击率 / 留资率**，优化只能靠 A/B 对比**整段**转化率，无法定位漏斗中段流失。
- 升 P0 后新增一处外部依赖（通道短链与点击回传），须纳入 blocking-external 跟踪。
