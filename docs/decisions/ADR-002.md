# ADR-002: 使用阿里云 RDS PostgreSQL 16 作为主数据库

## Status

Accepted (2026-09-18)

## Background

系统需要存储：产品包、标签字典、映射规则（条件为多变结构）、互斥组、房屋标签快照（约 125.7 万行、T+1 覆盖）、推送任务与明细（行数最大、需归档）、频控规则与名单、操作审计。数据源 MaxCompute 与阿里云生态同源。

关键需求：
- 规则条件是**可变结构**，需要无需 DDL 即可扩展的存储（JSON）。
- 推送明细持续增长，需要**分区 + 归档**能力。
- 需与 DataWorks 数据集成、MaxCompute 同地域同 VPC 低摩擦对接。

候选：

| 候选 | 版本 | 跑批适配 | JSON 存储 | 分区/归档 | MaxCompute 同生态 |
|------|------|----------|-----------|-----------|-------------------|
| RDS PostgreSQL | 16（18 可选） | 强 | 强（JSONB + GIN） | 强（声明式分区 + pg_partman） | 强（DataWorks 原生 Writer） |
| RDS MySQL | 8.0 | 强 | 中 | 中 | 强 |
| SQLite | 3.4x | 弱（写锁） | 弱 | 无 | 无 |
| MongoDB 类 | — | 中 | 强 | 中 | 弱 |

## Decision

选择 **阿里云 RDS PostgreSQL 16**（官方推荐为生产最稳定大版本；PG 18 已支持，可作为后续升级目标，可一键大版本升级）。

理由：
1. `JSONB` + GIN 索引承载规则条件与标签快照，规则变更无需改表结构。
2. 原生声明式分区（RANGE by `created_at`）+ `pg_partman` 管理 `push_detail` 的预建与归档，符合"分区数控制在几十个"的官方最佳实践。
3. DataWorks 数据集成原生支持 PostgreSQL Writer，同步链路最短、内网免公网流量费。
4. 单机即可支撑 125.7 万行快照 + 百万级明细，无需分库分表或大数据平台。

SQLite 被否决：每日百万级跑批 + 并发读写会触发写锁，不适合。

## Consequences

正面：
- 规则灵活、归档清晰、同步链路短。
- 事务与约束能力支撑跑批幂等（`stat_date` 唯一约束）。

负面：
- 分区表的唯一约束必须包含分区键（`push_detail` 不能有全局唯一键），实现时需注意。
- 需运维 PG 分区维护任务（`pg_partman`）。
